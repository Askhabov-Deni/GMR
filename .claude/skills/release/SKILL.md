# Выпуск версии GMR

Владелец говорит по-русски. Правила — docs/BUILD.md («Версии», «Проверка перед
выпуском»), docs/WORKFLOW.md. Здесь — порядок, который держим каждый раз.

## Нельзя

- Отправлять в GitHub или ставить метку без явного «Отправь» владельца. Сборка и
  коммит — по «закоммить и собери»; отправка — отдельным шагом.
- Класть в git персональные данные: фото, таблицы, базы, журналы, кропы, eval
  моделей надписи (`account_ocr/runs` — там номера счетов). Добавлять так:
  `git add -A -- . ':(exclude)account_ocr/runs'`. Хук `.githooks/pre-commit`
  остановит коммит с данными (`git config core.hooksPath .githooks` — если
  выключен).
- Трогать открытую у владельца программу (свой процесс GMR.exe) и его месяцы:
  проверки — только на копиях, копии потом удалить.

## Порядок

1. **Номер** — по таблице в docs/BUILD.md: исправления — PATCH, новое поведение
   по решению владельца («поведение» в CHANGELOG) — MINOR. `src/gmr/version.py`.
2. **CHANGELOG** — `docs/CHANGELOG.md`: заголовок «## Не выпущено» →
   «## Версия X.Y.Z — <сегодня>». Записи — что изменилось и почему, проверки
   цифрами; изменение результата — с пометкой «(поведение)».
3. **Проверка** — `.venv/Scripts/python.exe gmr.py check` (данные, ruff,
   тесты). Не зелёная — не коммитить, чинить. Python — только `.venv`
   (просто `python` — заглушка Магазина).
4. **Коммит** — сообщение «Версия X.Y.Z: <главное>», список изменений, в конце
   строка Co-Authored-By из системной подсказки.
5. **Сборка** — `.venv/Scripts/python.exe gmr.py build --out D:/GMR_build/X.Y.Z`
   (10–20 минут, в фоне). Сборка проверит `GMR.exe --version`, сделает архив
   `GMR X.Y.Z.zip`, сама выгрузит детекторы в OpenVINO, если надо.
6. **Проверка сборки** — сценарии окна через собранный exe:
   `.venv/Scripts/python.exe -m tools.ui_scenarios --from-month D:/GMR/Май_2026_v1.1 --exe D:/GMR_build/X.Y.Z/dist/GMR/GMR.exe`
   Копию месяца и новые фото программа готовит и удаляет сама. Нужно
   «ИТОГ: N из N» и строка «exe: ход виден». Если менялась обработка —
   ещё обработать exe-ом маленький месяц с нуля (`gmr.py month <временная
   папка> --clear-readings --table <таблица>` + 15 фото) и посмотреть журнал:
   «детектор счётчика: OpenVINO», «Фото N из M», показания записаны. Временный
   месяц удалить.
7. **Уборка** — `D:/GMR_build/X.Y.Z/work` удалить; оставить `dist` и архив.
8. **Отчёт владельцу** — где архив и exe, что проверено и чего не проверяли,
   что у него открыта прежняя версия (закрыть, `settings.json` скопировать из
   её папки). Последней строкой — вопрос: отправить X.Y.Z в GitHub и поставить
   метку vX.Y.Z — «Отправь» или «Сначала попробую»?

## По «Отправь»

```
git push origin main
git tag vX.Y.Z <коммит сборки>
git push origin vX.Y.Z
git ls-remote --tags origin vX.Y.Z      # метка на сервере
```

Метка — на коммит, из которого собрано (он в `ВЕРСИЯ.txt` сборки). После —
обновить заметку о версии в памяти проекта.
