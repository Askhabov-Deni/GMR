# GMR — чтение показаний газовых счётчиков по фото

Контролёры фотографируют счётчики. Программа по каждому фото находит
счётчик и его серийный номер, читает показания и записывает их в таблицу
абонентов. Фото, с которыми она не справилась, уходят на ручной разбор
оператору.

## Из чего состоит

| Часть | Что делает |
|---|---|
| `reader.py` | **Автоматическая обработка** папки с фото: модели → серийник → поиск в таблице → показание → запись в таблицу и лог, раскладка фото по папкам (`plus/`, `minus/`, `repeat/`, `question/<причина>/`) |
| `program2.py` | **Окно оператора**: разбор фото из `question/` (вкладка «Обработка») и выборочная проверка автоматических результатов (вкладка «Проверка») |
| `gmr.py` | Одна точка входа для команд: `process`, `analyze`, `inspect`, `weights` |
| `tools/` | Инструменты: качество чтения по логу, просмотр работы моделей, учёт файлов весов |
| `models/` | Код моделей: обучение, оценка, инференс (YOLO — детекция, CNN — цифры, CRNN — серийник) |
| `src/gmr/` | Общий код обеих программ: правила (domain), контракты моделей, работа с таблицей и логом |
| `archive/` | Старые утилиты, которые сейчас не используются (пояснения — `archive/README.md`) |

Как программы связаны через файлы — `docs/contract_reader_program2.md`.

## Установка (Windows, PowerShell)

Нужен Python 3.12–3.14. Команды выполнять в папке проекта.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python -m pytest tests/ -v
```

Если `pip.exe` после переноса папки перестал запускаться, используйте
`python -m pip` или пересоздайте `.venv`.

**Файлы весов моделей в git не хранятся.** Их нужно положить по путям из
`PipelineConfig` (`src/gmr/domain/config.py`). Какие именно файлы нужны и их
отпечатки (SHA-256) записаны в `docs/models.md`. Проверка:

```powershell
python gmr.py weights          # для каждой модели: путь, размер, отпечаток или «ФАЙЛ НЕ НАЙДЕН»
```

Для окна оператора нужен Tcl/Tk. Он входит в установщик с python.org;
если Python ставили из Microsoft Store, Tk может понадобиться отдельно.

## Работа

### 1. Автоматическая обработка
```powershell
python gmr.py process --input <папка с фото> --output <папка результатов> --table <таблица.csv|xlsx>
```
Без параметров берутся пути по умолчанию из `PipelineConfig`. Их можно
переопределить переменными окружения `GMR_INPUT_DIR`, `GMR_OUTPUT_DIR`,
`GMR_TABLE_PATH` (см. `.env.example`). `python reader.py` делает то же самое.

- Во входной папке могут лежать фото или подпапки контролёров («Аюб»,
  «Сулиман С», …). Результаты раскладываются по тем же подпапкам.
- Лог обработки пишется рядом с таблицей: `<таблица>_log.csv`.
- Повторный запуск по той же папке не трогает уже разобранные фото, а фото
  с автоматическими ошибками читает заново.
- В каждой папке результатов есть `report.txt` с итогами.

Таблица — CSV или Excel со столбцами «Номер счетчика», «Лицевой счет»,
«Последние показания», «Текущие показания». Программа заполняет
«Текущие показания».

### 2. Ручной разбор
```powershell
python program2.py
```
При первом запуске укажите имя оператора, **папку контролёра** (например
`output\Аюб`, а не общую `output\`), таблицу и папку для разметки.

На вкладке «Обработка» у каждого фото из `question/` есть кнопки:
- «Принять»;
- «Дубль»;
- «Нечитаемо»;
- «Нет в базе»;
- «Серийник в базе с ошибкой» — номер в базе записан с опечаткой. Фото уходит
  в `db_serial_fix/` со списком для исправления базы, показание в таблицу
  не пишется.

Если серийника нет в таблице, программа подсказывает похожие номера из базы
с лицевым счётом и расходом. Вкладка «Проверка» — выборочная проверка
автоматических PLUS/MINUS.

### 3. Инструменты
```powershell
python gmr.py analyze <лог.csv> --table <таблица>   # качество чтения; --details — разбор ненайденных серийников
python gmr.py inspect photo <фото или папка>        # что видят модели; режимы: meter, digits, serial, digit, photo
python gmr.py weights --write                       # обновить таблицу весов в docs/models.md
```

## Тесты
```powershell
python -m pytest tests/ -v
```
Тесты не требуют весов моделей: модели в них поддельные. Тестам окон
`program2.py` нужен экран, без него они пропускаются (`skipped`); на Linux
их запускают через `xvfb-run`.
