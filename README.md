# GMR — чтение показаний газовых счётчиков по фото

Контролёры фотографируют счётчики. Программа по каждому фото находит
счётчик и его серийный номер, читает показания и записывает их в таблицу
абонентов. Фото, с которыми она не справилась, уходят на ручной разбор
оператору.

## Из чего состоит

| Часть | Что делает |
|---|---|
| `reader.py` | **Автоматическая обработка** фото месяца: модели → серийник → поиск в таблице абонентов → показание → запись в базу месяца, раскладка фото по папкам (`plus/`, `minus/`, `repeat/`, `question/<причина>/`) |
| `program2.py` | **Окно оператора**: разбор фото из `question/` (вкладка «Обработка») и выборочная проверка автоматических результатов (вкладка «Проверка») |
| `gmr.py` | Одна точка входа для команд: `month`, `export`, `process`, `analyze`, `inspect`, `weights`, `check` |
| `tools/` | Инструменты: качество чтения по логу, просмотр работы моделей, учёт файлов весов |
| `models/` | Код моделей: обучение, оценка, инференс (YOLO — детекция, CNN — цифры, CRNN — серийник и лицевой счёт по надписи маркером) |
| `src/gmr/` | Общий код обеих программ: правила (domain), контракты моделей, папка и база месяца |
| `archive/` | Старые утилиты, которые сейчас не используются (пояснения — `archive/README.md`) |

Как программы связаны через файлы — `docs/contract_reader_program2.md`.

## Установка (Windows, PowerShell)

Нужен Python 3.12–3.14. Команды выполнять в папке проекта.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python gmr.py check
```

Если `pip.exe` после переноса папки перестал запускаться, используйте
`python -m pip` или пересоздайте `.venv`.

**Файлы весов моделей в git не хранятся.** Их нужно положить по путям из
`PipelineConfig` (`src/gmr/domain/config.py`). Какие именно файлы нужны и их
отпечатки (SHA-256) записаны в `docs/models.md`. Проверка:

```powershell
python gmr.py weights          # для каждой модели: путь, размер, отпечаток или «ФАЙЛ НЕ НАЙДЕН»
```

Для окна оператора нужен Tcl/Tk. Он входит в установщик с python.org;
если Python ставили из Microsoft Store, Tk может понадобиться отдельно.

## Работа

### 1. Папка месяца
Один месяц — одна папка: в ней фото, результат, база `gmr.sqlite`, выгрузка.
```powershell
python gmr.py month D:\GMR\Октябрь_2026 --table <таблица компании.xls>   # создать месяц / загрузить обновлённую таблицу
python gmr.py month D:\GMR\Октябрь_2026                                   # сводка
python gmr.py export D:\GMR\Октябрь_2026                                  # выгрузить ещё раз
```
Таблица компании (`.xls`, `.xlsx` или `.csv`) копируется в базу месяца
`gmr.sqlite`; исходный файл не меняется. Результат — `показания.xlsx` (те же
столбцы) и `лог.csv`. Отчёт загрузки — в `таблицы\`.

В таблице компании нужны столбцы «Номер счетчика», «Лицевой счет»,
«Последние показания», «Текущие показания». Программа заполняет «Текущие
показания» (в выгрузке — ещё «Дата» и «Разница»).

### 2. Автоматическая обработка
```powershell
python gmr.py process D:\GMR\Октябрь_2026      # то же: python reader.py D:\GMR\Октябрь_2026
```
- Фото кладите только в `фото\<контролёр>\` («Аюб», «Сулиман С», …) и только
  докладывайте — программа папку `фото\` не меняет. Если в корне `фото\`
  лежит фото, прогон не начнётся. Результат раскладывается по тем же папкам
  в `результат\`.
- Показание и строка лога пишутся в базу одной записью: сбой посреди прогона
  или открытый в Excel `показания.xlsx` не теряют показаний. В конце —
  выгрузка `показания.xlsx` и `лог.csv`.
- Каждый запуск читает только **новые** фото: разобранные раньше и тот же
  файл под другим именем пропускаются молча (в отчёте — сколько). Фото с
  ошибкой ждёт оператора и заново не читается; заново — по
  `python gmr.py process <месяц> --reread` (например после замены модели) и
  само, если номера не было в таблице, а после её обновления он появился.
- Когда у счёта появилось показание, его фото, которые ждали оператора
  («цифры», «подозрительно»), уходят в `repeat\`.
- Файлы, которые программа не берёт (`.webp`, `.heic`, видео, папки внутри
  папки контролёра), перечислены в `report.txt` и в журнале прогона.
- Итог месяца — `python gmr.py month <месяц>`: сколько показаний записано и
  кем, кто без показания (полный список — `без_показаний.csv` в папке
  месяца), сколько фото ждут оператора и почему.
- В каждой папке результата есть `report.txt` с итогами, а в
  `результат\run_logs\` — журнал каждого прогона (последние 30), в том
  числе причина, если прогон прервался.
- Перед каждым прогоном и при запуске окна оператора база месяца
  копируется в `gmr_backups\<дата_время>\` (последние 30 копий).
- Исправления оператора для дообучения моделей окно кладёт в
  `разметка\` папки месяца; в датасеты их забирает
  `python gmr.py datasets --collect <месяц>` (`docs/GUIDE.md`, раздел 4).

Старого режима (`--input`, `--output`, `--table`, таблица с CSV-логом рядом)
с этапа 2.3b нет. Старый `<таблица>_log.csv`, если он лежит рядом с таблицей
при создании месяца, переносится в базу.

### 3. Окно оператора — весь месяц без PowerShell
```powershell
python gmr.py shortcut     # один раз: ярлык «Счётчики» на рабочем столе
python program2.py         # или так — из PowerShell
```
Инструкция для оператора со снимками экрана — **`docs/OPERATOR.md`**.

При первом запуске укажите имя и **папку месяца**: «Открыть…» — готовый
месяц, «Новый месяц…» — создать из таблицы компании. Окно показывает фото всех контролёров сразу (столбец
«Контролёр»), показания и решения пишет в базу месяца.

Всё, что раньше делалось командами, — в окне:
- **«▶ Обработать новые»** — то же, что `gmr.py process <месяц>`, с полосой
  прогресса и кнопкой «Остановить» (прогон дочитывает текущее фото и
  заканчивает; остальные — в следующий раз). Пока идёт обработка, разбирать
  фото нельзя; в конце — итог обработки и обновлённая очередь.
- **«Итог месяца»** — то же, что `gmr.py month <месяц>`.
- Меню **«Месяц»**: «Новый месяц…» и «Обновить таблицу компании…» (то же,
  что `gmr.py month <папка> --table <таблица>`), «Открыть папку месяца»,
  «Открыть другой месяц…», «Прочитать заново фото с ошибками…» (то же, что
  `process --reread`).

На вкладке «Обработка» у каждого фото из `question/` есть кнопки:
- «Принять» (если у счёта уже есть показание — окно покажет его и спросит
  «Заменить?»);
- «Дубль»;
- «Нечитаемо»;
- «Нет в базе»;
- «Серийник в базе с ошибкой» — номер в базе записан с опечаткой. Номер в
  базе месяца исправляется на номер с фото, показание записывается сразу,
  фото уходит в `plus/` или `minus/`. Номер попадает в список для компании
  `db_serial_fix.csv` в папке месяца.

Если серийника нет в таблице, программа подсказывает похожие номера из базы
с лицевым счётом и расходом. Вкладка «Проверка» — выборочная проверка
автоматических PLUS/MINUS.

Кнопка «Выгрузить показания» (вверху справа) пишет `показания.xlsx` и
`лог.csv`; при закрытии окна выгрузка делается сама. Если `показания.xlsx`
открыт в Excel — программа попросит его закрыть («Повторить») или выйти без
выгрузки (показания сохранены в базе, выгрузить можно потом:
`python gmr.py export <папка месяца>`).

### 4. Инструменты
```powershell
python gmr.py analyze <месяц>\лог.csv --table <месяц>\показания.xlsx   # качество чтения; --details — разбор ненайденных серийников
python gmr.py inspect photo <фото или папка>        # что видят модели; режимы: meter, digits, serial, digit, photo
python gmr.py weights --write                       # обновить таблицу весов в docs/models.md
python gmr.py datasets                              # датасеты моделей: папки database\datasets\ и их проверка (docs/GUIDE.md, 5.0)
python gmr.py prelabel <папка с фото>               # предразметка YOLO текущей моделью
python gmr.py etalon add <месяц>; python gmr.py etalon check   # эталон трудных фото: сравнить модели (docs/GUIDE.md, 5.4)
python gmr.py check                                 # перед коммитом: данные, код, тесты
```

## Тесты и проверка перед коммитом
```powershell
python gmr.py check            # всё сразу: данные не попадают в git, ruff, тесты
python -m pytest tests/ -v     # только тесты
```
Тесты не требуют весов моделей: модели в них поддельные. Тестам окон
`program2.py` нужен экран, без него они пропускаются (`skipped`); на Linux
их запускают через `xvfb-run`.

`xfailed` — **известные ошибки** (`tests/test_known_issues.py`): тест
описывает, как должно быть, и пока падает. Когда ошибку исправят, pytest сообщит об этом — пометку снимают.
Сейчас (этап 3a) известных ошибок нет.
