## Зачем

Детектор счётчика (YOLO, классы `meter`, `serial`, `account`) не находит
табличку на ~11% фото и показания — на ~3% (архив 2026-10, 15 538 фото).
Чтобы его доучить, нужны фото именно с этими промахами, размеченные вручную.
Сейчас удобного инструмента нет: `gmr.py prelabel` пишет рамки модели в
файлы, но исправлять их негде, и непроверенная рамка неотличима от
проверенной.

Цель — **свой разметчик**: открываешь папку фото, видишь фото, при желании —
что нашла модель; правишь, удаляешь, дорисовываешь, переходишь к следующему.
Один инструмент на любой YOLO-датасет проекта (`meter_yolo`, `digits_yolo`).

## Что получается на выходе

- Формат — как сейчас у датасетов детекторов (`docs/DATASETS.md`): рядом с
  папкой фото `images\` — `labels\<имя фото>.txt`, строка на рамку:
  `класс cx cy w h` (доли от ширины и высоты фото, 6 знаков), `classes.txt` —
  названия классов по строкам. Если папка фото не `images\` — разметка рядом
  с фото (как у `prelabel`).
- Пустой `.txt` = «проверено: на фото ничего нет». Его пишет только человек
  (кнопка «На фото ничего нет»), никогда — модель.
- Фото **никогда** не меняются, не переименовываются и не переносятся.
- Готовую папку переносят в `database\datasets\meter_yolo\` как обычно,
  потом `python gmr.py datasets` (проверка) и `python gmr.py etalon exclude`
  (счета эталона архива — вне обучения).

## Главное правило: проверено ≠ предложено моделью

Рамки модели — **предложение**, а не разметка. Пока человек не подтвердил
фото, в `labels\` для него ничего не пишется: обучение берёт только то, что
видел человек.

- Предложения модели хранятся отдельно: `labels\.predictions\<фото>.json`
  (рамки, классы, уверенность, какие веса, какой порог).
- Статус каждого фото — `labels\.status.json`:
  - `new` — не открывалось;
  - `predicted` — модель предложила, человек не проверил;
  - `done` — человек подтвердил (файл `.txt` записан);
  - `empty` — человек подтвердил: объектов нет (пустой `.txt`);
  - `skip` — пропущено (плохое фото, не счётчик); в `labels\` ничего нет.
- Уже существующие `.txt` при первом открытии папки: если файл писал
  `prelabel` (сейчас — `D:\16k\yolo_разметка`), различить нельзя — поэтому
  при открытии спросить один раз: «Файлы разметки уже есть (N). Это ваша
  проверенная разметка или предразметка модели?» — и пометить `done` или
  `predicted` соответственно.

## Окно

Тот же стек, что у окна оператора: **tkinter + Pillow**, без новых
библиотек (на рабочем компьютере уже есть, работает через `pythonw`).
Готовые программы (CVAT, Label Studio — веб, сервер, тяжело; LabelImg —
заброшен, без модели) не подходят: нужны своя логика статусов, классы
проекта, модель проекта, кириллица в путях.

```
┌──────────────────────────────────────────────────────┬──────────────────┐
│                                                      │ Фото 128 из 2004 │
│                                                      │ ▓▓▓▓░░░░ 6%      │
│               фото (масштаб, сдвиг)                  │ статус: predicted│
│      рамки: сплошные — свои, пунктир — модели        ├──────────────────┤
│      у рамки — класс и (у модели) уверенность        │ Объекты:         │
│                                                      │ ■ meter   0.93   │
│                                                      │ ■ serial  0.41 ⚑ │
│                                                      │ + account        │
│                                                      ├──────────────────┤
│                                                      │ Модель: вкл.     │
│                                                      │ Порог: ──●── 0.25│
│                                                      │ Показать: ☑ ☑ ☑  │
├──────────────────────────────────────────────────────┴──────────────────┤
│ 1 meter  2 serial  3 account │ Enter — готово, далее │ ← → │ Ctrl+Z │ ? │
└─────────────────────────────────────────────────────────────────────────┘
```

### Работа с рамками

- **Новая рамка:** выбрать класс (клавиши `1`/`2`/`3` или кнопка), потянуть
  мышью. Перекрестие на весь экран — чтобы точно попасть в край.
- **Выделить:** щелчок по рамке (по краю — если рамки наложились; `Tab` —
  следующая рамка).
- **Двигать:** тянуть выделенную; **размер:** 8 ручек по углам и сторонам;
  стрелки — сдвиг на 1 пиксель фото, `Shift`+стрелки — на 10.
- **Класс:** выделить и нажать `1`/`2`/`3`.
- **Удалить:** `Delete`.
- **Рамка модели:** щелчок — выделить; `Enter` на выделенной — принять;
  правка любой рамки модели делает её своей. `A` — принять все рамки модели
  на фото; `X` — отклонить все.
- Рамка не выходит за фото (обрезается по краю), меньше 4×4 пикселей фото —
  не создаётся (случайный щелчок).
- **Отмена/повтор:** `Ctrl+Z` / `Ctrl+Y`, на всё в пределах фото.

### Просмотр

- Колесо — масштаб к курсору; правая кнопка (или пробел + мышь) — сдвиг;
  `F` — вписать фото в окно; `0` — 100%.
- Фото показывается уменьшенным (фото 4000×3000 на экран), координаты
  рамок — всегда в пикселях исходного фото.
- `H` — скрыть/показать все рамки (посмотреть, что под ними).
- Поворот фото по EXIF — **так же, как его видит обучение**: читать через
  `src/gmr/render/image_io.read_image` (OpenCV), не через голый Pillow
  (Pillow EXIF не учитывает — рамки съедут). Тест на фото с EXIF-поворотом.

### Переход по фото

- `Enter` (без выделения) — «готово»: записать `.txt`, статус `done`, к
  следующему. `→`/`←` — следующее/предыдущее **без** подтверждения (правки
  сохраняются как черновик в `.status.json`, статус не меняется).
- `E` — «на фото ничего нет» (`empty`), `S` — пропустить (`skip`).
- `N` — следующее непроверенное; `G` — перейти по имени/номеру.
- Фильтр очереди: по статусу; «модель не нашла класс X» (например, только
  фото без `serial` — ради них разметка и затевается); список фото из файла
  (например, отобранный по `сборка.csv`).
- Прогресс: «проверено N из M», скорость, «осталось ~X мин».
- Закрыл окно — при следующем открытии та же папка, то же фото.

## Модель (необязательно)

- Включается в окне или ключом `--weights`; по умолчанию — детектор
  счётчика из настроек (`PipelineConfig.meter_detect_model`). Без модели
  разметчик работает полностью (torch/ultralytics не загружаются).
- Предсказания — в фоне: пока человек размечает фото, модель считает
  следующие 3–5. Окно не подвисает.
- Кэш предсказаний на диске (`labels\.predictions\`), привязка к весам
  (отпечаток файла весов): то же фото с теми же весами второй раз не
  считается; другие веса — пересчёт.
- Порог уверенности — ползунок (по умолчанию 0.25, как у `prelabel`):
  модель считает один раз с низким порогом (0.05), ползунок только
  фильтрует показ — без пересчёта.
- Рамки модели с уверенностью ниже рабочего порога программы
  (`meter_conf_thresh`, 0.7) — помечены ⚑: в работе программа их бы не
  взяла. Это и есть главные кандидаты на доучивание.
- Имена классов модели — через `standard_class` (`gas_meter` → `meter` …);
  порядок классов — по `classes.txt` папки, если он есть; если у модели и
  у `classes.txt` классы расходятся — предупредить и не смешивать номера.

## Проверки при «готово»

Не запрещают, а предупреждают (жёлтая строка, `Enter` ещё раз — сохранить):

- больше одной рамки `meter` / `serial` / `account` (обычно по одной);
- нет `meter` (обычно есть всегда);
- две рамки одного класса почти совпадают (IoU > 0.9) — дубль;
- рамка принята из модели без правки при уверенности < 0.3 — «проверьте».

Сколько рамок каждого класса допустимо — настройка (у `digits_yolo` цифр
до 5–8).

## Надёжность и данные

- Запись `.txt` и `.status.json` — через временный файл и переименование:
  сбой посреди записи не портит разметку.
- Перед первой правкой существующего `.txt` — копия в
  `labels\.backup\` (один раз на файл).
- Пути с кириллицей и пробелами (`D:\16k\yolo_разметка`) — обязательно;
  тест с такими путями.
- Ничего не уходит в сеть. Фото и разметка — персональные данные, в
  репозиторий не попадают (как и весь `database\`).

## Устройство кода

- `src/gmr/labeling/` — логика без окна: чтение/запись YOLO, перевод
  координат (фото ↔ экран при масштабе и сдвиге), рамки (создать, двигать,
  тянуть за ручку, обрезать по фото), статусы и черновики, отмена/повтор,
  проверки при «готово», кэш предсказаний. Всё — обычными тестами.
- `tools/labeler.py` — окно (tkinter), только отрисовка и события.
- Модель — через тот же `YOLO(...)`, что `prelabel` (одна функция
  предсказания на оба).
- Тесты окна — через `xvfb-run`, как у окна оператора; мутационная проверка
  к логике.
- `prelabel` после разметчика: оставить для пакетной предразметки, но
  писать в `.predictions\`, а не в `.txt` — решить вместе с этапом 2.
