# Сборка программы для офиса

Собранная программа — одна папка **«GMR Оператор»**, Python на компьютере
оператора не нужен. В папке:

- **`GMR Оператор.exe`** — окно оператора; его и запускают.
- **`gmr.exe`** — обработка фото и команды (`gmr.exe month …`, `gmr.exe
  shortcut`…). Окно запускает его само по кнопке «Обработать новые фото».
- `_internal\` — всё остальное: Python, библиотеки, веса моделей. Её не
  трогать.

Почему папка, а не один файл: в программе PyTorch и модели — около 1 ГБ.
Один exe распаковывал бы этот гигабайт во временную папку Windows при каждом
запуске: долго, и на диске C: должно быть столько свободного места.

## Почему два exe

Оба из одной сборки и делят одну папку `_internal\`.

| | `GMR Оператор.exe` | `gmr.exe` |
|---|---|---|
| Что это | окно оператора | обработка фото и команды |
| Кто запускает | оператор (ярлык) | окно — по кнопке «Обработать новые фото»; владелец — вручную |
| Окно | обычное, без чёрного окна | консольное (текст) |
| Нейросети | не грузит (окно открывается за пару секунд) | грузит модели и читает фото |

Обработка — отдельной программой, потому что ей нужен вывод строк
(«Фото 13 из 24…» — по ним окно рисует полосу), а окну, запущенному
ярлыком, консоль не нужна. Если обработка упадёт, окно останется открытым и
покажет, что случилось. То же у владельца без сборки: `gmr_operator.py` и
`gmr.py`.

## Как собрать

На компьютере разработчика, в папке проекта (в `.venv` — PyInstaller:
`python -m pip install pyinstaller`), код закоммичен:

```powershell
python gmr.py build                     # → D:\GMR_build\dist\GMR Оператор\ и D:\GMR_build\GMR Оператор X.Y.Z.zip
git tag vX.Y.Z; git push origin vX.Y.Z  # метка: какой коммит собран
```

Сборка — 10–20 минут. `python gmr.py build` по очереди: проверяет, что код
закоммичен (версия = коммит), собирает PyInstaller'ом (`packaging/gmr.spec`),
кладёт рядом с exe `ВЕРСИЯ.txt` (версия, дата, коммит, файлы весов с
SHA-256), проверяет `gmr.exe --version` и упаковывает папку в архив. В сборку
попадают веса, которые сейчас в `PipelineConfig` (`src/gmr/domain/config.py`):
сменили модель — соберите заново. Нет файла весов — сборка останавливается
и пишет, какого.

## Версии

Номер — `MAJOR.MINOR.PATCH` (`src/gmr/version.py`):

| Что изменилось | Номер | Пример |
|---|---|---|
| исправлены ошибки, мелочи вида окна; как читаются фото и что пишется в месяц — так же | PATCH | 1.0.0 → 1.0.1 |
| новое или изменённое поведение по решению владельца («поведение» в CHANGELOG): правила, другая модель, новые функции окна; старые месяцы открываются | MINOR | 1.0.1 → 1.1.0 |
| несовместимо: месяц прошлой версии не открыть без перевода или оператор работает по-другому | MAJOR | 1.4.2 → 2.0.0 |

Порядок выпуска: в `src/gmr/version.py` — новый номер, в `docs/CHANGELOG.md`
заголовок «Версия X.Y.Z — дата» над записями этой версии, коммит,
`python gmr.py build`, метка `vX.Y.Z`. Версию видно в заголовке окна, в
журнале каждой обработки (`результат\run_logs\`), в `ВЕРСИЯ.txt` и в
свойствах exe — по ней ясно, какая программа прочитала месяц.

## Как поставить в офисе

1. Распаковать архив **`GMR Оператор X.Y.Z.zip`** (или скопировать папку
   «GMR Оператор» целиком), например в `D:\`. Папки месяцев — отдельно, где
   удобно. Новая версия — распаковать поверх старой (или рядом и перенести
   `settings.json`); месяцы не трогаются.
2. Один раз — ярлык на рабочем столе: в папке программы
   `gmr.exe shortcut` (или ярлык на `GMR Оператор.exe` вручную).
3. Дальше — как в `docs/OPERATOR.md`.

Настройки окна (`settings.json`) и журнал окна (`program2.log`) — рядом с
exe. Если программа стоит в `C:\Program Files\`, туда нужно право записи —
проще поставить её в папку пользователя или на `D:\`.

## Что внутри устроено иначе, чем из папки проекта

`src/gmr/frozen.py`: веса и образцы символов ищутся в `_internal\`,
настройки и журнал окна — рядом с exe; окно запускает обработку как
`gmr.exe process <месяц>`. Без сборки всё как раньше.
