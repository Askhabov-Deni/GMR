# Сборка программы для офиса

Собранная программа — архив **«GMR X.Y.Z.zip»**, в нём одна папка
«GMR». Python на компьютере оператора не нужен. В папке:

- **`GMR.exe`** — одна программа: окно оператора; обработку фото
  она запускает сама.
- **`ПРОЧТИ.txt`** — как поставить (первое, что видно в архиве).
- **`Инструкция оператора.html`** — `docs/OPERATOR.md` одним файлом со
  снимками, открывается любым браузером; в окне — «Справка» → «Инструкция
  оператора».
- `ВЕРСИЯ.txt` — версия, дата сборки, коммит, файлы весов.
- `_internal\` — всё остальное: Python, библиотеки, веса моделей. Её не
  трогать.

Почему папка, а не один файл: в программе PyTorch и модели — около 1 ГБ.
Один exe распаковывал бы этот гигабайт во временную папку Windows при каждом
запуске: долго, и на диске C: должно быть столько свободного места.

## Одна программа

С 1.1.0 (просьба владельца) `gmr.exe` нет. Обработку фото окно запускает
тем же `GMR.exe` с параметрами: `GMR.exe process
<месяц>` — без окна, строки «Фото 13 из 24…» идут окну, по ним оно рисует
полосу. Обработка — отдельным процессом той же программы, а не внутри окна:
модели (около 1 ГБ памяти) грузятся только на время обработки, а если
обработка упадёт, окно останется открытым и покажет, что случилось.

Остальные команды `gmr.py` тоже работают в собранной программе
(`GMR.exe month <папка>`, `--version`), но оператору они не нужны:
ярлык — «Справка» → «Ярлык на рабочем столе», новый месяц и таблица — меню
«Месяц». У владельца без сборки — как раньше: `gmr_operator.py` (окно) и
`gmr.py` (команды).

## Как собрать

На компьютере разработчика, в папке проекта (в `.venv` — PyInstaller:
`python -m pip install pyinstaller`), код закоммичен:

```powershell
python gmr.py build                     # → D:\GMR_build\dist\GMR\ и D:\GMR_build\GMR X.Y.Z.zip
git tag vX.Y.Z; git push origin vX.Y.Z  # метка: какой коммит собран
```

Сборка — 10–20 минут. `python gmr.py build` по очереди: проверяет, что код
закоммичен (версия = коммит), собирает PyInstaller'ом (`packaging/gmr.spec`),
кладёт рядом с exe `ВЕРСИЯ.txt`, `ПРОЧТИ.txt` и «Инструкцию оператора»
(`tools/manual_html.py`), проверяет `GMR.exe --version` и
упаковывает папку в архив. В сборку попадают веса, которые сейчас в
`PipelineConfig` (`src/gmr/domain/config.py`): сменили модель — соберите
заново. Нет файла весов — сборка останавливается и пишет, какого.

С 1.6.0 детекторы (счётчик, цифры) в сборке — ещё и в формате OpenVINO
(папка `best_openvino_model` рядом с `best.pt`, `python gmr.py openvino`).
Сборка выгружает их сама, если выгрузки нет или она от прежних весов
(отпечаток `best.pt` — в `веса.txt` выгрузки). Из пакета OpenVINO в сборку
идёт только расчёт на процессоре: без видеокарты, нейропроцессора,
конвертеров и телеметрии. Работает на любом 64-битном Intel или AMD; не
запустился — обработка идёт через PyTorch, в журнале прогона — почему.

## Проверка перед выпуском

```powershell
python gmr.py check                                                    # тесты и данные
python -m tools.ui_scenarios <КОПИЯ месяца> --photos <папка новых фото> --exe "D:\GMR_build\dist\GMR\GMR.exe"
python -m tools.doc_screenshots                                        # снимки инструкции (если менялось окно; окно — за краем экрана)
```

`tools/ui_scenarios.py` проходит окно с клавиатуры, как оператор: «Проверка»,
«Очередь» со всеми горячими клавишами, настройки, «Справка», меню «Месяц»,
обработка фото — в Python и через собранный exe. Месяц меняется — только
копия. В конце — «ИТОГ: N из M проверок прошли».

## Версии

Номер — `MAJOR.MINOR.PATCH` (`src/gmr/version.py`):

| Что изменилось | Номер | Пример |
|---|---|---|
| исправлены ошибки, мелочи вида окна; как читаются фото и что пишется в месяц — так же | PATCH | 1.0.0 → 1.0.1 |
| новое или изменённое поведение по решению владельца («поведение» в CHANGELOG): правила, другая модель, новые функции окна; старые месяцы открываются | MINOR | 1.0.1 → 1.1.0 |
| несовместимо: месяц прошлой версии не открыть без перевода или оператор работает по-другому | MAJOR | 1.4.2 → 2.0.0 |

Порядок выпуска: в `src/gmr/version.py` — новый номер, в `docs/CHANGELOG.md`
заголовок «Версия X.Y.Z — дата» над записями этой версии, коммит,
`python gmr.py build`, метка `vX.Y.Z`. Версию видно в заголовке окна, в
«Справка» → «О программе», в журнале каждой обработки
(`результат\run_logs\`), в `ВЕРСИЯ.txt` и в свойствах exe — по ней ясно,
какая программа прочитала месяц.

## Как поставить в офисе

1. Распаковать архив **`GMR X.Y.Z.zip`**, например в `D:\`. Папки
   месяцев — отдельно, где удобно. Новая версия — распаковать поверх старой;
   месяцы не трогаются, `settings.json` (имя оператора, месяц) остаётся.
2. Открыть `GMR.exe`, «Справка» → «Ярлык на рабочем столе».
3. Дальше — как в инструкции оператора.

Настройки окна (`settings.json`) и журнал окна (`program2.log`) — рядом с
exe. Если программа стоит в `C:\Program Files\`, туда нужно право записи —
проще поставить её в папку пользователя или на `D:\`.

## Что внутри устроено иначе, чем из папки проекта

`src/gmr/frozen.py`: веса и образцы символов ищутся в `_internal\`,
настройки и журнал окна — рядом с exe; с параметрами программа работает
как `gmr.py` и подключает вывод к тому, кто её запустил
(`attach_std_streams`). Без сборки всё как раньше.
