## 1. Как программа читает фото

Четыре модели работают по очереди:

```
фото
 └─ ① YOLO «детектор счётчика»  → находит две рамки: счётчик (gas_meter)
 │                                 и табличку с номером (serial_number)
 ├─ табличка ─ ② CRNN «серийник» → строка цифр номера + уверенность
 │              └─ поиск номера в таблице абонентов → лицевой счёт,
 │                 прошлое показание
 └─ счётчик ── ③ YOLO «детектор цифр» → 5 рамок, по одной на барабан
                 └─ каждая цифра ─ ④ CNN «цифра» → 0–9 + уверенность
                    └─ 5 цифр → показание → сравнение с прошлым
```

Пятая модель — необязательная: ⑤ CRNN «надпись маркером» читает лицевой
счёт, написанный контролёром на корпусе, и сверяет его с серийником
(раздел 5.6). Пока путь к её весам пуст, её нет.

Итог по каждому фото — **исход**. По нему фото кладётся в свою папку:

| Исход | Что значит | Папка |
|---|---|---|
| PLUS | всё прочитано, показание больше прошлого, записано в таблицу | `plus/` |
| MINUS | прочитано, но показание меньше прошлого (у вас это нормально), записано | `minus/` |
| REPEAT | это фото уже разобрано или показание по этому счёту уже записано | `repeat/` |
| SERIAL_NOT_FOUND | номер прочитан, но в таблице такого нет | `question/serial_not_found/` |
| NO_SERIAL / SERIAL_LOW_CONF | таблички не нашли / номер прочитан неуверенно | `question/…` |
| NO_METER | счётчик не нашли | `question/no_meter/` |
| DIGITS_ERROR | не уверена в цифрах показания | `question/digits_error/` |
| SUSPICIOUS | разница с прошлым показанием больше порога, или в таблице показание уже стоит, а в логе о нём нет записи | `question/suspicious/` |
| ERROR | программа упала на этом фото (ошибка модели, файл не читается). Прогон идёт дальше, при следующем прогоне фото читается заново | `question/error/` |
| SERIAL_AMBIGUOUS | номер счётчика в таблице у нескольких лицевых счетов (у одной записи в базе номер с ошибкой) — показание не пишется, оператор выбирает абонента | `question/serial_ambiguous/` |

Где что в коде:
- `reader.py` — весь путь фото: шаги, исходы, папки, запись в базу месяца;
- `src/gmr/domain/` — правила без моделей и файлов: настройки и пороги
  (`config.py`), что считать повтором, как сверять номер;
- `src/gmr/application/` — «прочитать фото моделями» (этой функцией
  пользуются и `reader.py`, и `program2.py`, поэтому читают они одинаково),
  создание месяца и выгрузка (`month.py`), действия окна оператора
  (`operator.py`);
- `src/gmr/ml/` — подключение моделей: `loader.py` загружает веса,
  `adapters.py` приводит ответы моделей к общему виду;
- `src/gmr/storage/` — папка и база месяца (`month.py`), чтение таблицы
  компании (`register.py`), лог обработки, копии базы;
- `models/` — код самих моделей: обучение, оценка, запуск.

**Все настройки** (пути к весам, пороги уверенности, имена столбцов) —
в одном месте: `src/gmr/domain/config.py`, класс `PipelineConfig`.

## 2. Работа каждый день

**Оператору PowerShell не нужен** (этап 4): ярлык «Счётчики» на рабочем
столе (создаётся один раз: `python gmr.py shortcut`), в окне — «Новый
месяц…», «▶ Обработать новые», «Итог месяца», «Выгрузить показания».
Инструкция со снимками экрана — `docs/OPERATOR.md`. Те же действия
командами (для владельца):

```powershell
cd C:\AD\GSM\gas-meter-reader
.\.venv\Scripts\Activate.ps1

# 0) в начале месяца — папка месяца из таблицы компании (один раз;
#    обновлённую таблицу — той же командой)
python gmr.py month D:\GMR\Октябрь_2026 --table <таблица компании.xls>
#    фото из WhatsApp кладите в D:\GMR\Октябрь_2026\фото\<контролёр>\

# 1) автоматическая обработка
python gmr.py process D:\GMR\Октябрь_2026

# 2) ручной разбор того, что не получилось (в настройках — папка месяца)
python program2.py

# 3) как сработало (качество)
python gmr.py analyze D:\GMR\Октябрь_2026\лог.csv --table D:\GMR\Октябрь_2026\показания.xlsx
```

- Фото за месяц только докладывайте в `фото\<контролёр>\` (в корень `фото\`
  нельзя — прогон не начнётся). Каждый `process` читает только новые фото,
  разобранные пропускает; фото с ошибкой ждёт оператора. После замены модели
  — `python gmr.py process <месяц> --reread`: фото с ошибками читаются заново.
- Когда у счёта появилось показание, его фото, ждавшие оператора («цифры»,
  «подозрительно»), сами уходят в `repeat\`.
- Как идёт месяц — `python gmr.py month <месяц>`: записано (программа /
  оператор / было в таблице), без показания (список — `без_показаний.csv`),
  ждут оператора по причинам. Файлы, которые программа не берёт (не
  `.jpg/.png`), — в `report.txt`.
- В каждой папке результатов лежит `report.txt` с итогами прогона.
- Показания и лог — в базе месяца `gmr.sqlite`; руками их не правят.
  Компании отдают `показания.xlsx`: его пишет `process` в конце прогона,
  кнопка «Выгрузить показания» в `program2.py` и закрытие окна.
- `program2.py` показывает фото всех контролёров сразу (столбец «Контролёр»).
- На вкладке «Проверка» в `program2.py` время от времени проверяйте
  автоматические PLUS/MINUS. Каждая проверка — правильный ответ для оценки
  моделей (`analyze` → «Точность по проверке оператора»).

Перед обновлением кода всегда: `python gmr.py check` (данные не попадают в
git, ошибок в коде нет, тесты прошли). В конце должно быть «ВСЁ В ПОРЯДКЕ».
`xfailed` в тестах — это известные ошибки, так и должно быть
(`tests/test_known_issues.py`).

## 3. Как показать проект

### Подготовка (один раз, 15 минут)
1. Сделайте демо-папку **без настоящих данных абонентов**: 20–30 фото
   разного качества (хорошие, размытые, без таблички) и маленькую таблицу
   с выдуманными лицевыми счетами под номера на этих фото.
2. Прогоните её заранее, чтобы знать, что покажет программа.

### Показ (10 минут)
1. **Проблема.** «Контролёры приносят сотни фото. Раньше каждое
   переписывали вручную.»
2. **Автоматика.** `python gmr.py month demo\Месяц --table demo\table.csv`, фото — в
   `demo\Месяц\фото\<контролёр>\`, затем `python gmr.py process demo\Месяц`
   — покажите, как фото разложились по папкам в `результат\`, откройте
   `report.txt` и `показания.xlsx`.
3. **Что видит модель.** `python gmr.py inspect photo demo\Месяц\фото\<контролёр>\<фото>.jpg`
   — откройте картинку из `inspect_out\`: рамки счётчика и таблички,
   прочитанные цифры с уверенностью. Это нагляднее всего.
4. **Человек в цепочке.** `python program2.py` → разбор одного фото из
   `question/`. Покажите подсказку похожих номеров из базы.
5. **Цифры** (с ваших реальных прогонов, 1111 фото, сентябрь 2026):
   - 58% фото обработано полностью автоматически (PLUS + MINUS);
   - 97.4% автоматических показаний верны по проверке оператора
     (116 проверенных фото одного контролёра);
   - подсказка серийника — 7 верных из 7;
   - остальное уходит оператору с указанием причины, а не теряется.
6. **Развитие.** Каждое исправление оператора сохраняется как пример для
   дообучения (раздел 4), то есть модели улучшаются от работы.

Честно говорите, что 97.4% — на небольшой выборке. Цифра станет надёжнее,
когда на вкладке «Проверка» накопятся сотни проверок.

## 4. Откуда берутся данные для дообучения

`program2.py` **сам и молча** сохраняет примеры, на которых модель
ошиблась, — **в папку месяца**, `<месяц>\разметка\` (с 2026-10-11: на рабочем
компьютере папки проекта с датасетами может не быть, папка месяца есть всегда):

```
<месяц>\разметка\
  digits_cnn\0\ … 9\       кропы цифр, которые оператор ИСПРАВИЛ
                           (папка = правильная цифра; <фото>__2026-10__digit_<N>.jpg)
  serials_crnn\images\      кропы табличек, где номер ИСПРАВИЛИ: <номер>__<фото>__2026-10.jpg,
  serials_crnn\labels\      правильный номер — <номер>__<фото>__2026-10.txt
  meter_yolo\               «Нет счётчика», а оператор ввёл показание — исходное фото
```

На компьютере разработки разметку месяца забирает в датасеты одна команда
(копирует, папку месяца не меняет, повторный запуск ничего не дублирует):

```powershell
python gmr.py datasets --collect D:\GMR\Октябрь_2026
```

Она кладёт файлы в `database\datasets\<датасет>\new\<ГГГГ-ММ>\` (месяц — по
дате создания папки месяца; он же в имени файла, чтобы после переноса в
датасет было видно, откуда пример). Эталон из того же месяца —
`python gmr.py etalon add <месяц>` (5.4).

`<фото>` — отпечаток фото: разные фото (и один счётчик в разные месяцы)
никогда не совпадут по имени, одно и то же фото не сохранится дважды.

Фото эталона (каждое третье трудное, 5.4) сюда не попадают: эталон и
обучение не пересекаются.

Когда сохраняется:
- **цифра** — только если оператор поменял её в показании. Сохраняются
  только изменённые позиции, верные цифры не сохраняются;
- **серийник** — если оператор ввёл номер, отличный от прочитанного, и
  при «Серийник в базе с ошибкой» (номер на фото верный).

Что важно знать:
- Это **самые ценные** примеры — именно те, где модель ошибается. Но их
  мало, и они «трудные». Обучать только на них нельзя: их подмешивают к
  старому датасету.
- Оператор тоже ошибается. Перед обучением **просмотрите папки глазами**
  (Проводник → «Крупные значки»): в `cnn/7/` должны лежать семёрки.
  Лишнее удалите.
- CRNN понимает только **цифры** длиной 4–10 символов. Номер с буквами
  при обучении будет пропущен.
- Делайте копию `database\datasets\` вместе с копией весов.

Сколько нужно, чтобы был смысл: ориентир — **от 200–300 исправленных
цифр** для CNN и **от 100–200 табличек** для CRNN.

## 5. Дообучение моделей на той же архитектуре

### Золотые правила
1. **Старые веса не трогать.** Каждое обучение — в **новую** папку.
   Прод работает на старых весах, пока вы не поменяете путь в
   `PipelineConfig`.
2. **Одна модель за раз.** Иначе не поймёте, что помогло.
3. **Сравнивать на одних и тех же реальных фото**, а не только по
   `val_acc` из обучения. В новом датасете другой тестовый набор,
   поэтому сравнивать числа обучения со старыми нечестно.
4. **Записать, что сделано:** строка в «Истории замен» в
   `docs/models.md`.

### 5.0. Где лежат датасеты (этап 5)

Все датасеты — в `database\datasets\` (в git не попадают). Команда
`python gmr.py datasets` создаёт недостающие папки (ничего не переносит
и не удаляет) и показывает, что лежит в каждом датасете и что не так.
Её вывод можно прислать: в нём только числа.

| Папка | Модель | Что внутри |
|---|---|---|
| `meter_yolo\` | детектор на фото (показания, серийник, лицевой счёт) | `images\`, `labels\`, `classes.txt`; `new\<месяц>\` — фото на ручную разметку |
| `digits_yolo\` | детектор цифр на кропе показаний | `images\`, `labels\`, `classes.txt` (`digit`) |
| `digits_cnn\` | цифра (CNN) | `0\` … `9\`; `new\<месяц>\0\` … `9\` — цифры, исправленные оператором |
| `serials_crnn\` | серийник (CRNN) | `images\`, `labels\<имя>.txt` (номер); `new\<месяц>\images\`, `labels\` — серийники, исправленные оператором |
| `accounts_crnn\` | лицевой счёт по надписи маркером (CRNN, 5.6) | `images\`, `labels\<имя>.txt` (что написано, например `00065`) |
| `etalon\` | эталон для сравнения моделей | в обучение не идёт |

- Датасет — **одна папка без train/val**: новые файлы просто докладываются.
- Обучение само делит датасет при запуске — **по фото**: кропы одного
  фото (`<фото>__…`) всегда в одной части. Часть определяется
  отпечатком имени фото, поэтому новые фото не перетасовывают старые.
- Что попало в обучение и что в проверку — `split\*.txt` в папке
  результата обучения; там же `run_info.json`: отпечаток датасета, коммит
  кода, версии пакетов. В папке датасета ничего не появляется.
- **`new\` обучение не читает.** Туда попадает разметка месяцев
  (`gmr.py datasets --collect <месяц>`, раздел 4). Просмотрите её и
  перенесите хорошие примеры в датасет сами.
- Точность после этапа 5 со старыми числами (`test_acc 0.974` у
  `v3_platinum`) не сравнивать: раньше цифры одного фото попадали и в
  обучение, и в тест, и число было завышено. Сравнивать — на реальных
  фото (5.4).

### 5.1. CNN — модель цифр (чаще всего нужна именно она)

```powershell
# 1) просмотреть кропы в database\datasets\digits_cnn\new\<месяц>\<цифра>\ (Проводник → «Крупные значки»)
#    и перенести хорошие в database\datasets\digits_cnn\<цифра>\
python gmr.py datasets

# 2) дообучить от текущих весов, маленький шаг обучения
#    (результат — новая папка meter_ocr\runs\cnn\runs\<дата-время>)
python models\cnn\train_cnn.py --finetune meter_ocr\runs\cnn\runs\v3_platinum\best.pth --lr 1e-4

# 3) отчёт: точность по классам, матрица ошибок, картинки ошибок
python models\cnn\evaluate_cnn.py --run_dir meter_ocr\runs\cnn\runs\<дата-время>

# 4) старая и новая модель на одних и тех же реальных цифрах
python gmr.py inspect digit <папка с кропами цифр>
python gmr.py inspect digit <папка с кропами цифр> --weights meter_ocr\runs\cnn\runs\<дата-время>\best.pth
```

`--finetune` или с нуля? `--finetune` — продолжить от текущих весов:
быстро, модель «доучивается». С нуля (без `--finetune`, `--lr` по
умолчанию) — если датасет сильно вырос или поменялся.

### 5.2. CRNN — модель серийника

Картинка `images\<имя>.jpg` и номер в `labels\<имя>.txt` (только цифры,
4–10 штук).

```powershell
# 1) просмотреть database\datasets\serials_crnn\new\<месяц>\images\ (номер — в начале имени файла)
#    и перенести хорошие: new\<месяц>\images\ → images\, new\<месяц>\labels\ → labels\
python gmr.py datasets

# 2) обучение заново (результат — serial_id_ocr\runs\crnn\<дата-время>\): кроп — с пропорциями,
#    край номера не срезается (этап 6c)
python models\crnn\train_crnn.py
#    дообучить прежнюю модель её же способом (растяжение, как до 6c):
python models\crnn\train_crnn.py --finetune serial_id_ocr\runs\crnn\2026-06-05_01-09\best.pt --input stretch --lr 1e-4

# 3) отчёт: точность всего номера, точность по позициям, ошибки
python models\crnn\evaluate_crnn.py --run_dir serial_id_ocr\runs\crnn\<дата-время> `
    --images_dir database\datasets\serials_crnn\images --labels_dir database\datasets\serials_crnn\labels

# 4) сравнение на реальных фото и на эталоне (5.4)
python gmr.py inspect serial <папка с фото>
python gmr.py inspect serial <папка с фото> --weights serial_id_ocr\runs\crnn\<дата-время>\best.pt
python gmr.py etalon check --serial-weights serial_id_ocr\runs\crnn\<дата-время>\best.pt
```

С этапа 6c `best.pt` помнит, как кроп приводился к размеру при обучении
(`input_mode`), и программа читает им так же. Старые веса (без этой
пометки) читаются по-старому — растяжением, так что работа программы не
меняется, пока вы не поставите новую модель.

Смотрите `plot_position_acc.png`: если ошибки на первой и последней
позиции, сначала проверьте кроп (`docs/BACKLOG.md`, задача 2), а не
переобучайте.

### 5.3. YOLO — детекторы

Детекторам нужна **разметка рамками** в формате YOLO: `labels\<фото>.txt`,
строка «класс cx cy w h» (доли от 0 до 1), названия классов — в
`classes.txt` (строка 1 — класс 0). Разметчик — любой с форматом YOLO
(Label Studio, CVAT, LabelImg).

```powershell
# 1) предразметка: текущая модель ставит рамки на фото без разметки
#    (готовую разметку не трогает; где не нашла ничего — файла нет)
python gmr.py prelabel database\datasets\meter_yolo\images
# 2) поправить рамки в разметчике, проверить
python gmr.py datasets
# 3) обучение: деление на обучение и проверку — при запуске (около 20% фото на проверку)
python models\yolo_all_detect\train_yolo.py --data database\datasets\meter_yolo `
    --model yolov8s.pt --project meter_detect\runs\detect --name meter_v2 --imgsz 640 --epochs 200
```

### 5.4. Эталон: сравнить модели «было → стало» (этап 5b)

Эталон — трудные фото с правильным ответом оператора: модель не
справилась, а оператор ввёл показание («Принять», «Серийник в базе с
ошибкой»), или модель прочитала, а оператор исправил на «Проверке». В
эталон идёт каждое третье такое фото (по отпечатку), остальные — в
обучение: одно и то же фото не бывает и там и там.

```powershell
# пополнить эталон из месяца (можно запускать сколько угодно раз — повторов не будет)
python gmr.py etalon add D:\GMR\Октябрь_2026
# из старого лога (до папок месяца): лог + папка, где лежат исходные фото
python gmr.py etalon add <таблица>_log.csv --photos <папка с фото>
# что в эталоне
python gmr.py etalon
# как читают эталон модели, которые в работе (настройки — 5.7: --month, --missing-digit, …)
python gmr.py etalon check
# то же с другим файлом весов или с запасом вокруг рамки серийника
python gmr.py etalon check --serial-weights serial_id_ocr\runs\crnn\<дата-время>\best.pt
python gmr.py etalon check --serial-pad 0.05
```

`check` выводит таблицу по причинам: сколько фото модель прочитала бы
сама и верно, и отдельно — **«уверенно, но неверно»** (опасные ошибки:
неверный номер или показание с уверенностью — так показание записалось бы
не тому абоненту или с ошибкой). Вывод — только числа, его можно
прислать. Результат по каждому фото — `database\datasets\etalon\checks\`.

Ниже — таблица порогов (этап 6c): при пороге 0.3 … 0.9 сколько фото
модель приняла бы сама и сколько из них неверно — отдельно для цифр (все
5 уверенно, без подстановок) и для серийника. Лучший порог — самый
низкий, при котором «неверно» = 0. Пороги в работе —
`digit_conf_thresh` и `serial_conf_thresh` в `src\gmr\domain\config.py`
(менять — решение владельца).

Правило замены (решение владельца 2026-10-04): новая модель ставится,
только если на эталоне она не хуже старой ни в одной строке таблицы
(включая «уверенно, но неверно») и лучше в той, ради которой меняли.

Запас вокруг рамки серийника посмотреть глазами:
`python gmr.py inspect serial <папка с фото> --serial-pad 0.05`.

### 5.7. Настройки распознавания месяца (пресет)

У каждого месяца свои настройки распознавания (решение владельца
2026-10-11). При создании месяца окно показывает их, заполненные как в
открытом месяце; потом — «Месяц» → «Настройки распознавания…». Действуют
со следующей обработки (и в окне — для подсказок модели). Хранятся в базе
месяца; видны в «Итоге месяца» и в журнале каждого прогона.

| Настройка | Варианты (первый — как было до настроек) |
|---|---|
| Детектор не нашёл одну цифру (сотни, десятки или единицы) | подставить «5» / прочитать моделью на этом месте (вырезать цифру между соседями; неуверенно — как любая неуверенная цифра) / отдать оператору |
| Неуверенные последние цифры | прощать две последние / последнюю / не прощать — к оператору |
| Прощённую цифру заменять | «0» / ответом модели (её цифрой, хоть и неуверенной) |
| Запас вокруг рамки серийника | 0% / 5% / 10% |
| Лицевой счёт по надписи маркером | нет / да — только когда модель надписи подключена (5.6) |
| Дополнительно: правило барабана | выключено / включено: неуверенная цифра, у модели две лучшие — соседние (3 и 4, 9 и 0) и вместе уверенные → барабан между ними, берётся меньшая (между 9 и 0 — 9) |
| Дополнительно: старшая цифра по прошлому показанию | выключено / включено: неуверенна только первая цифра, и цифра прошлого показания — среди двух лучших у модели → берётся она |
| Дополнительно: на фото ничего не найдено — повернуть | выключено / включено: детектор на фото не нашёл вообще ничего → то же фото, повёрнутое на 90°, 180°, 270° (первый поворот, где нашлись показания); в результат кладётся повёрнутое фото — счётчик стоит прямо |
| Дополнительно: серийник по таблице | выключено / включено: номера нет в таблице или он неуверенный → номер таблицы, на который картинка похожа больше всего, если его доля не меньше 0.9; иначе — оператору с подсказкой «ближе всех …» |

Что даст настройка — до того, как её включать, — показывает эталон:

```powershell
python gmr.py etalon check                                 # как было до настроек
python gmr.py etalon check --month D:\GMR\Октябрь_2026      # с настройками месяца
python gmr.py etalon check --missing-digit model           # пропущенную цифру — моделью
python gmr.py etalon check --forgive-with model            # вместо «0» — ответ модели
python gmr.py etalon check --forgive-last 0                # не прощать последние
python gmr.py etalon check --drum-rule                     # правило барабана
python gmr.py etalon check --first-from-last               # старшая цифра по прошлому показанию
python gmr.py etalon check --month D:\GMR\Октябрь_2026 --serial-by-table   # номера — из таблицы месяца
python gmr.py etalon check --turn-photo                    # ничего не найдено — повернуть фото
```

Для старшей цифры эталону нужно прошлое показание: с 2026-10-11 `etalon add`
его записывает, а старым строкам эталона дописывает при следующем
`etalon add` того же месяца. Самое важное в выводе — колонка «уверенно, но
неверно»: серийник по таблице может уверенно взять чужой номер.

С 2026-10-11 эталон сравнивает показание **целиком**: «0» вместо настоящей
цифры — неверное показание (раньше две последние цифры не сравнивались).
Подставленные цифры видны в notes лога: «подставлено: pos2='5' (цифра не
найдена)», «… — прочитано моделью на её месте», «(прочитано 7, conf=…) —
неуверенно, взято как есть», «pos2='3' (барабан между 4 и 3, conf=…)»,
«pos0='1' (по прошлому показанию; модель: 7 0.500 / 1 0.300)»; серийник по
таблице — «серийник по таблице: прочитано 123465, взят 123456 (доля 0.97)»
или «… не уверен — ближе всех 123456 (доля 0.62)»; повёрнутое фото — «фото
повёрнуто на 90°: на исходном детектор ничего не нашёл».

## 6. Смена архитектуры модели

### Что можно менять свободно
Программа общается с моделью через **контракт**
(`src/gmr/domain/ml.py`). Например, для модели цифр: «дай кроп цифры —
верни цифру и уверенность 0..1». Всё, что выполняет контракт, подходит:
другая CNN, ResNet, MobileNet, хоть чужая библиотека.

### Ловушка, о которой нужно знать
Сейчас веса грузятся так: код **создаёт модель по текущему
`models/cnn/model_cnn.py`** и вкладывает в неё веса
(`DigitCNN.from_pretrained`). Если поменять слои в `model_cnn.py`,
**старые веса `v3_platinum` перестанут загружаться**, и прод сломается.
С CRNN то же самое (`models/crnn/model_crnn.py`). Как кроп серийника
приводится к размеру, чекпоинт CRNN с этапа 6c помнит сам (`input_mode`);
размер входа по-прежнему в `models/crnn/config_crnn.py`.

Поэтому правильный порядок такой:
1. **Новая архитектура — в новом файле**, например
   `models/cnn/model_cnn_v2.py` с классом `DigitNetV2`. Старый файл не
   трогать.
2. Обучение — копия `train_cnn.py` (или параметр «какую модель брать»).
   Препроцессинг (размер `IMG_SIZE`/`IMG_WIDTH`, нормализация
   `NORM_MEAN`/`NORM_STD`) при запуске должен быть **ровно тем же**, что
   при обучении. Если меняете его, делайте отдельный конфиг.
3. Инферер — класс с методом `predict(crop) → {"digit": int, "confidence": float}`
   (как `CNNInferer` в `models/cnn/infer_cnn.py`). Тогда адаптер
   `CnnDigitRecognizer` подходит как есть.
4. В `src/gmr/ml/loader.py` выбор: старая модель или новая (например, по
   полю в `PipelineConfig`). Так возврат — одна строка.
5. Тест в `tests/test_ml_interfaces.py`: новый адаптер выполняет контракт.
6. Сравнение — эталон (5.4) и ввод в работу (5.5).

Вариант проще: экспорт в **TorchScript**. `train_cnn.py` уже сохраняет
`best_model.pt`, а `CNNInferer` умеет его открыть без кода архитектуры.
Такой файл не зависит от `model_cnn.py`. Для CRNN такой загрузки пока
нет, её нужно добавить.

### Большие перемены
Пример: читать все 5 цифр показания одной моделью (как CRNN для
серийника) вместо «детектор цифр + CNN». Это меняет не одну модель, а
шаг: `read_meter_digits` в `src/gmr/application/recognition.py`, правила
подстановки цифр, пометки в логе. Это **изменение поведения**: план,
решение, отдельная ветка, сравнение на одних и тех же фото
(`docs/WORKFLOW.md`).

## 8. Словарь

- **Кроп** — вырезанный кусок фото (табличка, счётчик, одна цифра).
- **Уверенность (confidence)** — насколько модель уверена, от 0 до 1.
  Ниже порога (0.6–0.7, `config.py`) ответ не принимается.
- **Веса** — файл `.pt`/`.pth`, «знания» обученной модели. В git не
  хранятся, их нужно беречь.
- **Датасет** — примеры с правильными ответами для обучения.
- **train/val/test** — три части датасета: на одной учим, на второй
  выбираем лучшую эпоху, на третьей честно проверяем.
- **Эпоха** — один проход обучения по всему датасету.
- **Дообучение (fine-tune)** — продолжить обучение готовой модели на
  новых данных.
- **Отпечаток (SHA-256)** — уникальный «код» файла. Совпал — файл тот же.
- **Контракт** — договорённость «что модель получает и что отдаёт».
