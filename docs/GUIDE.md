## 1. Как программа читает фото

Четыре модели работают по очереди:

```
фото
 └─ ① YOLO «детектор счётчика»  → находит две рамки: счётчик (gas_meter)
 │                                 и табличку с номером (serial_number)
 ├─ табличка ─ ② CRNN «серийник» → строка цифр номера + уверенность
 │              └─ поиск номера в таблице абонентов → лицевой счёт,
 │                 прошлое показание
 └─ счётчик ── ③ YOLO «детектор цифр» → 5 рамок, по одной на барабан
                 └─ каждая цифра ─ ④ CNN «цифра» → 0–9 + уверенность
                    └─ 5 цифр → показание → сравнение с прошлым
```

Итог по каждому фото — **исход**. По нему фото кладётся в свою папку:

| Исход | Что значит | Папка |
|---|---|---|
| PLUS | всё прочитано, показание больше прошлого, записано в таблицу | `plus/` |
| MINUS | прочитано, но показание меньше прошлого (у вас это нормально), записано | `minus/` |
| REPEAT | это фото уже разобрано или показание по этому счёту уже записано | `repeat/` |
| SERIAL_NOT_FOUND | номер прочитан, но в таблице такого нет | `question/serial_not_found/` |
| NO_SERIAL / SERIAL_LOW_CONF | таблички не нашли / номер прочитан неуверенно | `question/…` |
| NO_METER | счётчик не нашли | `question/no_meter/` |
| DIGITS_ERROR | не уверена в цифрах показания | `question/digits_error/` |
| SUSPICIOUS | разница с прошлым показанием больше порога, или в таблице показание уже стоит, а в логе о нём нет записи | `question/suspicious/` |
| ERROR | программа упала на этом фото (ошибка модели, файл не читается). Прогон идёт дальше, при следующем прогоне фото читается заново | `question/error/` |
| SERIAL_AMBIGUOUS | номер счётчика в таблице у нескольких лицевых счетов (у одной записи в базе номер с ошибкой) — показание не пишется, оператор выбирает абонента | `question/serial_ambiguous/` |

Где что в коде:
- `reader.py` — весь путь фото: шаги, исходы, папки, запись в таблицу и лог;
- `src/gmr/domain/` — правила без моделей и файлов: настройки и пороги
  (`config.py`), что считать повтором, как сверять номер;
- `src/gmr/application/` — «прочитать фото моделями». Этой функцией
  пользуются и `reader.py`, и `program2.py`, поэтому читают они одинаково;
- `src/gmr/ml/` — подключение моделей: `loader.py` загружает веса,
  `adapters.py` приводит ответы моделей к общему виду;
- `src/gmr/storage/` — таблица абонентов и лог обработки;
- `models/` — код самих моделей: обучение, оценка, запуск.

**Все настройки** (пути к весам, пороги уверенности, имена столбцов) —
в одном месте: `src/gmr/domain/config.py`, класс `PipelineConfig`.

## 2. Работа каждый день

```powershell
cd C:\AD\GSM\gas-meter-reader
.\.venv\Scripts\Activate.ps1

# 1) автоматическая обработка
python gmr.py process --input <папка с фото> --output <папка результатов> --table <таблица>

# 2) ручной разбор того, что не получилось
python program2.py

# 3) как сработало (качество)
python gmr.py analyze <таблица>_log.csv --table <таблица>
```

- Повторный `process` по той же папке не трогает уже разобранные фото, а
  фото с автоматическими ошибками читает заново.
- В каждой папке результатов лежит `report.txt` с итогами прогона.
- В `program2.py` указывайте **папку контролёра** (`output\Аюб`), а не
  общую `output\`, иначе увидите «0 из 0».
- На вкладке «Проверка» в `program2.py` время от времени проверяйте
  автоматические PLUS/MINUS. Каждая проверка — правильный ответ для оценки
  моделей (`analyze` → «Точность по проверке оператора»).

Перед обновлением кода всегда: `python gmr.py check` (данные не попадают в
git, ошибок в коде нет, тесты прошли). В конце должно быть «ВСЁ В ПОРЯДКЕ».
`xfailed` в тестах — это известные ошибки, так и должно быть
(`tests/test_known_issues.py`).

## 3. Как показать проект

### Подготовка (один раз, 15 минут)
1. Сделайте демо-папку **без настоящих данных абонентов**: 20–30 фото
   разного качества (хорошие, размытые, без таблички) и маленькую таблицу
   с выдуманными лицевыми счетами под номера на этих фото.
2. Прогоните её заранее, чтобы знать, что покажет программа.

### Показ (10 минут)
1. **Проблема.** «Контролёры приносят сотни фото. Раньше каждое
   переписывали вручную.»
2. **Автоматика.** `python gmr.py process --input demo\input --output demo\output --table demo\table.csv`
   — покажите, как фото разложились по папкам, и откройте `report.txt`.
3. **Что видит модель.** `python gmr.py inspect photo demo\input\<фото>.jpg`
   — откройте картинку из `inspect_out\`: рамки счётчика и таблички,
   прочитанные цифры с уверенностью. Это нагляднее всего.
4. **Человек в цепочке.** `python program2.py` → разбор одного фото из
   `question/`. Покажите подсказку похожих номеров из базы.
5. **Цифры** (с ваших реальных прогонов, 1111 фото, сентябрь 2026):
   - 58% фото обработано полностью автоматически (PLUS + MINUS);
   - 97.4% автоматических показаний верны по проверке оператора
     (116 проверенных фото одного контролёра);
   - подсказка серийника — 7 верных из 7;
   - остальное уходит оператору с указанием причины, а не теряется.
6. **Развитие.** Каждое исправление оператора сохраняется как пример для
   дообучения (раздел 4), то есть модели улучшаются от работы.

Честно говорите, что 97.4% — на небольшой выборке. Цифра станет надёжнее,
когда на вкладке «Проверка» накопятся сотни проверок.

## 4. Откуда берутся данные для дообучения

`program2.py` **сам и молча** сохраняет примеры, на которых модель
ошиблась. Папка задаётся в настройках `program2.py` («Папка для
разметки»). Внутри:

```
<папка разметки>/
  cnn/0/ … cnn/9/        кропы цифр, которые оператор ИСПРАВИЛ
                          (папка = правильная цифра)
  crnn/images/            кропы табличек, где номер ИСПРАВИЛИ:
                          12345678.jpeg + 12345678.txt (правильный номер)
```

Когда сохраняется:
- **цифра** — только если оператор поменял её в показании. Сохраняются
  только изменённые позиции, верные цифры не сохраняются;
- **серийник** — если оператор ввёл номер, отличный от прочитанного, и
  при «Серийник в базе с ошибкой» (номер на фото верный).

Что важно знать:
- Это **самые ценные** примеры — именно те, где модель ошибается. Но их
  мало, и они «трудные». Обучать только на них нельзя: их подмешивают к
  старому датасету.
- Оператор тоже ошибается. Перед обучением **просмотрите папки глазами**
  (Проводник → «Крупные значки»): в `cnn/7/` должны лежать семёрки.
  Лишнее удалите.
- CRNN понимает только **цифры** длиной 4–10 символов. Номер с буквами
  при обучении будет пропущен.
- Делайте копию папки разметки вместе с копией весов.

Сколько нужно, чтобы был смысл: ориентир — **от 200–300 исправленных
цифр** для CNN и **от 100–200 табличек** для CRNN.

## 5. Дообучение моделей на той же архитектуре

### Золотые правила
1. **Старые веса не трогать.** Каждое обучение — в **новую** папку.
   Прод работает на старых весах, пока вы не поменяете путь в
   `PipelineConfig`.
2. **Одна модель за раз.** Иначе не поймёте, что помогло.
3. **Сравнивать на одних и тех же реальных фото**, а не только по
   `val_acc` из обучения. В новом датасете другой тестовый набор,
   поэтому сравнивать числа обучения со старыми нечестно.
4. **Записать, что сделано:** строка в «Истории замен» в
   `docs/models.md`.

### 5.1. CNN — модель цифр (чаще всего нужна именно она)

Датасет CNN — простая структура «папка = цифра»:
`database/meter_ocr_data/cnn_dataset_gold/0/*.jpg … 9/*.jpg`
(путь — `CROPS_DIR` в `models/cnn/config_cnn.py`). Формат совпадает с
`<папка разметки>/cnn/`, поэтому новые кропы просто докладываются.

```powershell
# 0) копия датасета — чтобы можно было вернуться
Copy-Item database\meter_ocr_data\cnn_dataset_gold database\meter_ocr_data\cnn_dataset_v4 -Recurse

# 1) доложить проверенные кропы из program2 (для каждой цифры 0..9)
0..9 | ForEach-Object { Copy-Item "<папка разметки>\cnn\$_\*" "database\meter_ocr_data\cnn_dataset_v4\$_\" }

# 2) дообучить от текущих весов, маленький шаг обучения, НОВАЯ папка
python models\cnn\train_cnn.py --crops_dir database\meter_ocr_data\cnn_dataset_v4 `
    --output_dir meter_ocr\runs\cnn\runs\v4 `
    --finetune meter_ocr\runs\cnn\runs\v3_platinum\best.pth --lr 1e-4

# 3) отчёт: точность по классам, матрица ошибок, картинки ошибок
python models\cnn\evaluate_cnn.py --run_dir meter_ocr\runs\cnn\runs\v4 --crops_dir database\meter_ocr_data\cnn_dataset_v4

# 4) старая и новая модель на одних и тех же реальных цифрах
python gmr.py inspect digit <папка с кропами цифр>
python gmr.py inspect digit <папка с кропами цифр> --weights meter_ocr\runs\cnn\runs\v4\best.pth
```

`--finetune` или с нуля? `--finetune` — продолжить от текущих весов:
быстро, модель «доучивается». С нуля (без `--finetune`, `--lr` по
умолчанию) — если датасет сильно вырос или поменялся.

### 5.2. CRNN — модель серийника

Датасет CRNN — картинки и `.txt` с правильным номером, имена совпадают
(`123.jpeg` ↔ `123.txt`). Папки картинок и ответов можно указать одну и
ту же, как в `<папка разметки>/crnn/images`.

```powershell
# 1) собрать датасет: старые таблички + новые из program2 в одну НОВУЮ папку
#    (картинки → images\, .txt → labels\)

# 2) дообучение (результат — serial_id_ocr\runs\crnn\<дата-время>\)
python models\crnn\train_crnn.py --images_dir <images> --labels_dir <labels> `
    --save_dir serial_id_ocr\runs\crnn `
    --finetune serial_id_ocr\runs\crnn\2026-06-05_01-09\best.pt --lr 1e-4

# 3) отчёт: точность всего номера, точность по позициям, ошибки
python models\crnn\evaluate_crnn.py --run_dir serial_id_ocr\runs\crnn\<дата-время> --images_dir <images> --labels_dir <labels>

# 4) сравнение на реальных фото
python gmr.py inspect serial <папка с фото>
python gmr.py inspect serial <папка с фото> --weights serial_id_ocr\runs\crnn\<дата-время>\best.pt
```

Смотрите `plot_position_acc.png`: если ошибки на первой и последней
позиции, сначала проверьте кроп (`docs/BACKLOG.md`, задача 2), а не
переобучайте.

### 5.3. YOLO — детекторы (редко)

Детекторам нужна **разметка рамками** (прямоугольник вокруг счётчика,
таблички или каждой цифры), `program2.py` её не собирает. Нужно, только
если детектор часто не находит счётчик или цифры (NO_METER, «не 5 цифр»).
- Разметка: любой разметчик в формате YOLO (Label Studio, CVAT, Roboflow)
  или старый `archive/models/yolo_all_detect/labeler_yolo.py`.
- Разбивка: `python models\yolo_all_detect\train_val_split.py --images_dir … --labels_dir … --output_dir …`.
- Обучение: скрипт в архиве —
  `git mv archive/models/yolo_all_detect/detect_model_train.py models/yolo_all_detect/`,
  поменять в нём `data=`, `name=` (новое имя!) и, для дообучения,
  `YOLO('<старые>/best.pt')` вместо `yolov8n.pt`.

### 5.4. Ввод новой модели в работу (для любой)

```powershell
# 1) полный прогон тех же фото со СТАРОЙ моделью уже есть в логе — сохраните его копию
# 2) поменять путь в src\gmr\domain\config.py (например digit_ocr_model = ".../v4/best.pth")
python gmr.py check
# 3) прогон на копии тех же фото в НОВУЮ папку с НОВОЙ таблицей-копией
python gmr.py process --input <копия фото> --output <новая папка> --table <копия таблицы>
python gmr.py analyze <копия таблицы>_log.csv --table <копия таблицы>
# 4) сравнить с отчётом старой модели: DIGITS_ERROR / SERIAL_NOT_FOUND меньше?
#    PLUS+MINUS больше? точность по проверке оператора не упала?
# 5) если лучше:
python gmr.py weights --write      # новые отпечатки → docs/models.md
#    + строка в «Историю замен», + резервная копия нового файла
```

Если хуже — верните путь в `config.py`, и всё как было.

## 6. Смена архитектуры модели

### Что можно менять свободно
Программа общается с моделью через **контракт**
(`src/gmr/domain/ml.py`). Например, для модели цифр: «дай кроп цифры —
верни цифру и уверенность 0..1». Всё, что выполняет контракт, подходит:
другая CNN, ResNet, MobileNet, хоть чужая библиотека.

### Ловушка, о которой нужно знать
Сейчас веса грузятся так: код **создаёт модель по текущему
`models/cnn/model_cnn.py`** и вкладывает в неё веса
(`DigitCNN.from_pretrained`). Если поменять слои в `model_cnn.py`,
**старые веса `v3_platinum` перестанут загружаться**, и прод сломается.
С CRNN то же самое (`models/crnn/model_crnn.py`).

Поэтому правильный порядок такой:
1. **Новая архитектура — в новом файле**, например
   `models/cnn/model_cnn_v2.py` с классом `DigitNetV2`. Старый файл не
   трогать.
2. Обучение — копия `train_cnn.py` (или параметр «какую модель брать»).
   Препроцессинг (размер `IMG_SIZE`/`IMG_WIDTH`, нормализация
   `NORM_MEAN`/`NORM_STD`) при запуске должен быть **ровно тем же**, что
   при обучении. Если меняете его, делайте отдельный конфиг.
3. Инферер — класс с методом `predict(crop) → {"digit": int, "confidence": float}`
   (как `CNNInferer` в `models/cnn/infer_cnn.py`). Тогда адаптер
   `CnnDigitRecognizer` подходит как есть.
4. В `src/gmr/ml/loader.py` выбор: старая модель или новая (например, по
   полю в `PipelineConfig`). Так возврат — одна строка.
5. Тест в `tests/test_ml_interfaces.py`: новый адаптер выполняет контракт.
6. Сравнение — как в 5.4.

Вариант проще: экспорт в **TorchScript**. `train_cnn.py` уже сохраняет
`best_model.pt`, а `CNNInferer` умеет его открыть без кода архитектуры.
Такой файл не зависит от `model_cnn.py`. Для CRNN такой загрузки пока
нет, её нужно добавить.

### Большие перемены
Пример: читать все 5 цифр показания одной моделью (как CRNN для
серийника) вместо «детектор цифр + CNN». Это меняет не одну модель, а
шаг: `read_meter_digits` в `src/gmr/application/recognition.py`, правила
подстановки цифр, пометки в логе. Это **изменение поведения**: план,
решение, отдельная ветка, сравнение на одних и тех же фото
(`docs/WORKFLOW.md`).

## 7. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `ФАЙЛ НЕ НАЙДЕН` в `python gmr.py weights` | Веса не на месте. Положите их по пути из `docs/models.md` или поправьте путь в `config.py` |
| Отпечаток в `weights` не совпадает с `docs/models.md` | Файл весов подменили или испортили. Восстановите из копии |
| После правки `model_cnn.py` или `model_crnn.py` ошибка `size mismatch` / `Missing key` | Архитектура не совпадает с весами (раздел 6). Верните файл: `git checkout models/cnn/model_cnn.py` |
| «0 из 0» в `program2.py` | Укажите папку контролёра, а не общую `output\` |
| Тесты красные после обновления | Ничего не коммитить. `git stash` или `git checkout .` вернёт как было |
| Таблица или лог испортились, прогон прошёл не так | Копии «до прогона» — `gmr_backups\<имя таблицы>\<дата_время>\` рядом с таблицей. Что было в прогоне и почему он прервался — `<папка результатов>\run_logs\` |
| `pip.exe` не запускается | `python -m pip …` |
| Патч не применяется | `git pull`, затем снова. Если опять нет — проверить переводы строк (`docs/WORKFLOW.md`) |

## 8. Словарь

- **Кроп** — вырезанный кусок фото (табличка, счётчик, одна цифра).
- **Уверенность (confidence)** — насколько модель уверена, от 0 до 1.
  Ниже порога (0.6–0.7, `config.py`) ответ не принимается.
- **Веса** — файл `.pt`/`.pth`, «знания» обученной модели. В git не
  хранятся, их нужно беречь.
- **Датасет** — примеры с правильными ответами для обучения.
- **train/val/test** — три части датасета: на одной учим, на второй
  выбираем лучшую эпоху, на третьей честно проверяем.
- **Эпоха** — один проход обучения по всему датасету.
- **Дообучение (fine-tune)** — продолжить обучение готовой модели на
  новых данных.
- **Отпечаток (SHA-256)** — уникальный «код» файла. Совпал — файл тот же.
- **Контракт** — договорённость «что модель получает и что отдаёт».
