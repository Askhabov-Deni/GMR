# Стандарт датасетов

Решение владельца 2026-10-15. Одно правило для всех датасетов: **ответ виден
сразу** — в имени файла или в имени папки, без отдельных файлов разметки.
Нашли ошибку — переименовали файл (или перенесли кроп в другую папку цифры).

## Слова

Одно слово — одна вещь: в именах кропов, папок, классов детектора и в коде.

| Что | Слово | Прежние имена (программа понимает и их) |
|---|---|---|
| лицевой счёт (надпись маркером на корпусе) | `account` | `marker_id` |
| номер счётчика (табличка) | `serial` | `serial_number`, `serial_id` |
| рамка показаний | `meter` | `gas_meter` |
| цифра показаний | `digit` | — |

У уже обученного детектора YOLO классы зашиты в весах по-старому
(`gas_meter`, `serial_number`, `marker_id`) — программа понимает оба
варианта (`src/gmr/domain/datasets.standard_class`). В `classes.txt` для
следующего обучения детектора — новые слова: `meter`, `serial`, `account`.

## Имя кропа

```
<фото>__<что><№>[__<ответ>].jpg
```

- **фото** — имя исходного фото, обычно лицевой счёт: `1300000375` (код
  региона любой). Тот же счёт ещё раз (другой месяц) — `1300000375-2`. По
  фото обучение делит датасет: все кропы одного счётчика — в одной части.
- **что** — `serial`, `account` или `digit`; **№** — какой по счёту на фото
  (у цифры — место в показаниях, 1–5).
- **ответ** — что на кропе.

| Датасет | Пример | Где ответ |
|---|---|---|
| `serials_crnn\images\` | `1300000375__serial1__0070351.jpg` | в имени: номер с ведущими нулями, как в таблице |
| `accounts_crnn\images\` | `1300000375__account1.jpg` | сам счёт фото; если на кропе другой счёт — `<фото>__account1__<счёт>.jpg` |
| `digits_cnn\<цифра>\` | `1300000375__digit3.jpg` | папка (`0` … `9`); в имени цифры нет — перенесли кроп в другую папку, и ответ поменялся |

Расширение — `.jpg` (картинки `.png` — `.png`). Папки `labels\` у серийников
нет. Имя не по стандарту обучение не берёт, а `python gmr.py datasets`
показывает такие файлы.

Датасеты детекторов (`meter_yolo`, `digits_yolo`) — по-прежнему фото и
`labels\` с рамками (формат YOLO); фото называется по лицевому счёту.

## Откуда берутся кропы

- **Окно оператора** (тихая разметка) сохраняет исправленные кропы сразу по
  стандарту: фото — лицевой счёт строки, которую оператор принял.
  `python gmr.py datasets --collect <месяц>` забирает их в
  `<датасет>\new\<ГГГГ-ММ>\`; если такое имя в датасете уже есть, кроп
  получает «-2». Повторный запуск ничего не дублирует.
- **Сборщик датасета** — из папки фото и таблицы (ниже).

## Сборщик: папка фото + таблица → кропы

```powershell
python gmr.py datasets --build D:\фото_участка --table D:\таблица.xls
python gmr.py datasets --build D:\фото_участка --table D:\таблица.xls --only serials --out D:\серийники
```

- Фото называются по лицевому счёту: `1300000375.jpg` (`1300000375 (2).jpg` —
  тот же счёт). Кропы режут те же детекторы и так же, как в работе.
- Ответы: номер счётчика — из таблицы (текстом, с нулями); лицевой счёт —
  из имени фото; цифры — «Текущие показания» (5 знаков, нули слева: 2353 →
  `0`, `2`, `3`, `5`, `3`).
- Кроп не делается, если ответа нет или он неоднозначен: счёта нет в
  таблице, у счёта несколько номеров или показаний, показаний нет (тогда
  только номер и надпись), детектор не нашёл нужное или нашёл не 5 цифр.
- `--only serials accounts digits` — какие папки собрать (по умолчанию все).
- Результат — в `<папка фото>_датасет\` (или `--out`), раскладка как в
  `database\datasets\`: `serials_crnn\images\`, `accounts_crnn\images\`,
  `digits_cnn\0\` … `9\`. Имена не совпадают с кропами, которые уже есть в
  датасетах. Папка должна быть новой (повторно — в другую).
- Итог по причинам — в выводе (только числа), по каждому фото —
  `сборка.csv` в той же папке. Просмотрите кропы и перенесите в датасеты.

## Переход старых имён (разово)

```powershell
python gmr.py datasets --standard --month D:\Октябрь_2026                  # показать, что будет
python gmr.py datasets --standard --month D:\Октябрь_2026 --apply          # переименовать
python gmr.py datasets --standard-undo                                     # вернуть как было
```

- `serials_crnn`: `1300000143__serial_number_1_set1.jpeg` + подпись из
  `labels\` → `1300000143__serial1__0070351.jpg`; подписи переезжают в
  `serials_crnn\labels_before_standard\`.
- `accounts_crnn`: `1300000093__marker_id_1.jpeg` → `1300000093__account1.jpg`.
- `digits_cnn`: `1300000013__gas_meter_1__digit_3.jpg` → `1300000013__digit3.jpg`.
- Разметка окна старого вида (`<номер>__<отпечаток фото>__2026-10.jpg`,
  `<отпечаток>__2026-10__digit_3.jpg`): лицевой счёт находится по отпечатку
  в базе месяца (`--month`, можно несколько месяцев); не нашёлся — в имени
  остаётся отпечаток.
- Имя, которое не удалось разобрать, и серийник без годной подписи не
  трогаются — вывод показывает несколько примеров.
- Что во что переименовано — `database\datasets\standard_renames.csv`.

После перехода команда будет удалена: новые кропы сразу называются по
стандарту.
