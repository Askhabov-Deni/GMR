## 2026-10-01 — этап 2.2a: папка месяца, база, загрузка и выгрузка таблицы
Новые команды; `reader.py` и `program2.py` пока работают по-старому.
- `python gmr.py month <папка> --table <таблица компании>` — создать месяц
  или загрузить обновлённую таблицу (сверка по лицевому счёту), потом
  выгрузка. Без `--table` — сводка. `python gmr.py export <папка>` —
  выгрузить ещё раз.
- Таблица читается из `.xls` (так её присылают, нужен `xlrd`), `.xlsx`,
  `.csv`. Лицевой счёт-число → текст без «.0»; номера с лишними `. , /` по
  краям очищаются (список — в отчёте загрузки); номера у нескольких
  абонентов — в отчёте.
- База `gmr.sqlite`: абоненты, показания, журнал изменений «кто, когда,
  было → стало», лог обработки. Загрузка — одна транзакция: оборвалась —
  база как была. Перед обновлением — копия базы в `gmr_backups\`.
- При создании месяца из старой таблицы рядом лежащий `<таблица>_log.csv`
  переносится в базу целиком.
- Выгрузка `показания.xlsx`: те же столбцы, тот же порядок, типы ячеек как
  в исходнике, «Разница» — формулой; `лог.csv` — в формате старого лога.
  Если файл открыт в Excel — сообщение «Закройте…», прежняя выгрузка цела.

## 2026-10-01 — этап 2.1c: тесты окна на Windows (поведение не меняется)
- У владельца при первом запуске тестов окна на Windows 2 окна из ~30 не
  создались: Tcl не смог прочитать свой `init.tcl` («Can't find a usable
  init.tcl … No error», затем «invalid command name tcl_findLibrary»). Так
  бывает, когда в одном процессе подряд создаётся много окон; в работе
  `program2.py` окно одно. Тесты создают окно заново, до 3 раз
  (`tests/_window.py`).

## 2026-10-01 — этап 2.1b: фото, на котором программа упала (**поведение**)
Решение владельца 2026-10-01. Раньше ошибка на одном фото (ошибка модели,
файл не читается) останавливала весь прогон. Теперь:
- фото → `question/error/`, в логе исход `ERROR`, в `notes` — «ошибка
  программы: <что случилось>», в журнале прогона — подробности;
- прогон идёт дальше; при следующем прогоне фото читается заново, как
  любая авто-ошибка;
- в окне оператора — причина «Ошибка программы», в очереди последней;
- Ctrl+C и ошибки записи (например, переполнен диск) по-прежнему
  останавливают прогон.
Прогноз на реальных фото: прогоны 1111 фото проходили без падений, поэтому
`ERROR` — 0, результаты те же. Битый файл, который не открывается как
картинка, по-прежнему уходит в `question/no_meter/` (детектор получает пустое
изображение) — перевести его в `error/` можно отдельным решением.
